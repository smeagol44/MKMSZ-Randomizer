### Previously unnoticed precise Trace (11) recovery: status/DMA interrupt collision

At the last of 79 consecutive rejections in Trace 11, the native enqueue routine's **first** AI_STATUS read (CP0 `3,355,939,791`) sees `FULL|BUSY`. ## Trace (5) vs Trace (6): exact FIFO-recovery bifurcation (2026-10-09)

**New focused read-only reconstruction — no emulator, ROM patch or production change.** Reprocessed the original untruncated AI and VI host traces using the observer's `MZRHST1` 56-byte schema and recorded DMA completion Count. The comparison identifies the **immediate mechanism determining whether a rejected native PCM buffer leads to more rejections or rapid recovery**. It does **not** identify why the initial dangerous buffer/phase combination arose, nor prove the Inventory/portrait path triggered it.

The first FIFO-full read in Trace (5) is at relative host t=42.356981s; in Trace (6), first isolated failure is at t=122.456338s (all times relative to each run's first VI log event). **The audio service's VI-relative Count offset is almost identical at their respective first failures: 7,592 versus 7,596 Count.** Thus a large late VI/audio-service dispatch is not needed to explain the different recovery outcomes.

| Directly traced quantity at/after first failure | Severe Trace (5) | Isolated Trace (6) |
|---|---:|---:|
| FIFO head / queued tail when FULL | 1,600 / 1,472 bytes | 1,536 / 1,408 bytes |
| Head DMA end after first FULL read | +4,258 Count | +4,492 Count |
| Tail DMA end minus **next service** (positive = still queued) | **+4,222 Count** | **−30,628 Count** |
| AI_STATUS at next service | `40000000` = head BUSY | `00000000` = FIFO idle |
| New submission after previous failed output | 704 frames | 704 frames |
| AI_LEN read immediately after that submission | **0 bytes** (old head nearly completed) | **2,808 bytes** (new 704-frame head) |
| Consequence under native head-only feedback | Next generation may again be 704 frames; overflow loop | Next generation is 352 frames; normal 352/368/384 rhythm resumes |

**Mechanism:** The native enqueuer at `0x8008A500` fails without an AI write when FIFO FULL, but `audio_frame_build` at `0x8007D4A8` still calculates a new buffer via its existing `AI_LEN` head-only feedback. The rejected generation is skipped, the producer continues. Both failing first services see AI_LEN=0 and therefore generate the 704-frame maximum. The **next service** is the fork: if the old queued 1,472-byte tail has not quite drained, the 704-frame buffer goes into the tail and the following AI_LEN can read zero again; if a 1,408-byte tail has drained, 704 frames enter an empty FIFO as the head, AI_LEN reads nearly 2,816 bytes, and the next synthesis shrinks to its 352-frame minimum. The 64-byte tail difference equals **35,264 Count units** at the observed 551 Count/byte. Holding the Trace (5) measured phase fixed, a hypothetical 1,408-byte tail would finish about **31,042 Count units before** the next service instead of 4,222 after. This counterfactual explains the branch, not why the original native tail sizes differ.

**All four isolated failures** in Trace (6) show the same next-service-empty recovery condition: tail completion relative to next service of **−30,628, −31,264, −31,194, −34,804 Count**, respectively. Their next accepted 704/688-frame buffers are **heads** with AI_LEN feedback **2,808/2,744** bytes; none enters the repeated rejection cycle. Trace (5) instead records **80 rejections** at roughly four-VI intervals. Its repeated cycle eventually loses phase lock: at t≈47.691s an AI DMA completes at CP0 Count `2327134045`, **736 Count before** the next STATUS/service at `2327134781`; the FULL condition clears, subsequent accepted buffers return to 352/368/384, and no further rejects appear before trace end. The event timing proves the crossing, but the source of that submillisecond phase shift remains unlogged.

**New near-resonance observation:** In both runs, every accepted AI write with a recorded duration follows **551 Count units per PCM byte** (2,670/2,670 in Trace 5, 12,851/12,851 in Trace 6); every VI callback reports **811,092 Count** as the next VI interval. At stereo 16-bit, a nominal 368-sample buffer consumes `368×4×551=811,072` Count—**only 20 Count less than VI**. This quantized guest scheduling makes FIFO state near a DMA boundary sensitive to a few thousand Count units (well below 1 ms), without any gross missed AI interrupt. The separate host playback device uses 22,047Hz and has its independently proven queue-threshold discard mechanism; do not equate its nominal playback clock with the guest's quantized `551 Count/byte` DMA deadline. The 551 multiplier may reflect the pinned RMG core's integer timing approximation; these traces do not establish that RMG differs incorrectly from console hardware or that guest code is universally defective.

**Critical boundary of proof:** This closes the **local feedback instability/recovery mechanism**, not the entire production rich-Inventory upstream attribution. Neither tracer records controller changes, native audio task *generation IDs*, PI/portrait DMA start/end, Inventory selection/mode, or the rendering workload that might perturb the first phase crossing. The successful/negative cursor tests refute any assertion that cursor motion always triggers acceleration. A corrective proof at feedback sizing, native service release, task ownership, or emulator AI timing must be selected by direct evidence and separately runtime-validated. **Do not install an AI enqueue retry/spin-wait, remove rich text, or merge draft #156/#157.** Further blind manual repetition is not warranted. Retain the full source trace files outside GitHub; the ROM-free read-only [AI/VI feedback comparator](../tools/inventory_audio_phase_compare.py) can be rerun against the same observer-v1 headers without emulation. Local comparison tests against Trace (5), Trace (6), and normal-only pass; GitHub CI on this new script is not asserted.

### PCM feedback and sequenced time

`8007D3FC → 8007D4A8` first cleans sample DMA (`8007D860`; audio frame counter `800A7F60` increments at `8007D98C`), then submits previous `lastInfo` at `8007D4E8 → 8008A500`. Enqueue checks full at `8008A550 → 80092E90`; full returns `-1` without AI writes, accepted writes AI_DRAM/AI_LEN at `8008A57C/580`, returns zero. The diagnostic logs the failure and returns through the original epilogue.

At `8007D4F0`, enqueue's result is overwritten by a call to AI_LEN getter `8008A3C0`. New sample count follows the observed native constants:

`max(352, ((368 - (AI_LEN >> 2) + 320) & ~15) + 16)`

Assembly uses 16-bit masking/storage. Minimum/target globals are `800BA450/454`, reserve `800A8004`; configured maximum PCM capacity `800BA458=704`. An empty head produces 704. **The feedback reads remaining head bytes, not total head+tail occupancy.** A late service and subsequent adjacent services can change produced sample counts without increasing aggregate service frequency. This is a competing mechanism, not recovered chronology.

### Shared RSP and task lifetime

The VI handler queues the prior generated task before producing the next. Dispatcher refuses while active `8009A53C` is nonzero, otherwise transfers queued→active at `80000F80`, clears queued at `F88`. Running graphics (`800FEC24 >= 0`) causes yield flags `800C11E8/800BF35E` and request `8008A7E0`; audio starts after SP/yield handoff. Completion handler `80000B6C` checks `osSpTaskYielded` (`8008A800`), clears/completes the appropriate owner, dispatches or resumes graphics.

**Conditional static hazards:** queued is one pointer. Promotion `80000E3C` can replace it if it has not been consumed. Continued synthesis can reuse a PCM record or command list before a delayed generation completes. These conditions are **not observed** in the pair. Both endpoints have fresh=`lastInfo+8`, queued=active=0, SP status `243` (halt/broke), and no queued SP/DP task event. That excludes an unfinished task at capture, not a previous replaced generation. Rotating addresses require generation IDs to establish ownership.

## Minimum measurement and bounded manual experiment

More endpoint states cannot recover the missing producer/consumer chronology. The minimum useful event sequence spans a healthy period and first recurring rejection:

1. VI due/delivery Count; audio service Count and its already computed AI_LEN; frame/WESS/synth counters and rejection-counter change.
2. Accepted AI address/length; live FIFO status/head/tail and scheduled versus delivered AI-end Count.
3. Audio generation (frame number + rotating record/list), RSP start/yield/return and SP completion Count. Verify PCM completion before AI consumes it and before record/list reuse. Enqueue into a waiting AI tail can overlap RSP work; submission alone is not a violation. Addresses alone are insufficient.
4. Active host plugin accepted/dropped byte totals plus short wall-time audio recording/onset markers, to measure the audible loss budget.

Prefer observation-only **host hooks in the original RMG build** at existing AI_STATUS/AI_LEN accesses, AI writes/end, VI delivery and RSP task/event boundaries. This is a specific diagnostic design, not an implemented build. First pin actual Flatpak/RMG/core/RSP/RDP/audio identities and settings, then verify corresponding source. Gate on exact diagnostic ROM SHA/MD5/code, log signature/version and validated guest pointer ranges/offsets.
