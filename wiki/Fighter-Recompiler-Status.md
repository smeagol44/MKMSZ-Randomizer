**Generator v0 (2026-11-25; Implementation/CI-confirmed, static).**

- **Decompiler** (`decompile`): symbolic values (`proc` = the current process `*0x8014C31C`, `self` = its object `+0x418`, call results, loads), IDO shapes (forward branches as if/else; back branches as do-while; a branch-likely's delay slot on its taken path; the else-block's first instruction hoisted into that delay slot; jumps out of a loop as `break`). Known arguments fold branches: Rayden's lightning routine `0x80077DF8` gives Lightning with 0 and the reversed Lightning with 1.
- **Rules** (`generate.CALL_RULES`): MKT engine routines → steps (begin, sound, animation selection and phase animation, frame stepping, velocity, stop, face, sleep, jump, effect, no-repel, shakes, end), the dispatch tables (`do_special`, `do_body_propell`, `do_quick_special`), MKT strike records decoded from `0x800AFDB0[fighter]` (box, reaction, damage, chip), MKT reaction ids → meanings (`REACTION_MEANINGS`, one shared table), and shapes: a counted loop around a strike is a hit window (`on_hit` from the contact branch, `on_block` from the strike flag `0x8014C3B8`, `only_if` from the `opponent_unsettled` guard), a counted loop without one is `repeat`, the torpedo's shared-velocity loop is `carry`. Unnamed routines next to the move's body are followed; anything else is reported as unknown, not guessed.

- **Projectile rules (2026-11-26; Implementation/CI-confirmed, static).** `proj_process(child)` becomes a `projectile` step read from the child process (`generate.projectile`):
  - **art**: `get_char_ani` / `find_part` / `skip_frame`, and `char_ani_part2` (`0x8000D12C`: table 0, cursor at part 2; Rayden). A part played to its end with `mframew` before the flight is the forming part: the program starts at the next one (noted);
  - **checks** before the flight: a call to a routine that steps one frame, sleeps and strike-checks, with the box it passes (`strike_box_check`, Reptile's acid arc steps) or its record's (`proj_strike_check` `0x8007F878`, Rayden);
  - **flight**: `proj_set_xvel` (speed, frame rate), `proj_flight` (the strike record), process `+0x438` a flight callback (a hum when it plays a sound each time its counter runs out: the forceballs' `0x12` every 3);
  - **impact** (inline or the routine after the flight): `match_me_to_opponent` (at the opponent), `multi_adjust_xy` (adjust), its art and rate (`mframew` / `init_anirate`), sound, effect, `follow` when it copies the opponent's velocity (`+0xC` / `+0x10` from `+0x3BC`) each tick. A victim reaction that plays the attacker's sound (`his_ft_sound` `0x80005810`) puts it on the impact, as a host victim reaction plays none (Reptile's acid sizzle, reaction `0x72`);
  - **palette**: the one of the frame the object is made from (descriptor `+0x14`): a throw helper (token 11; Reptile's `0x315C` → `0x800BEC14`, `0x2FD4` → `0x800BECE4`) or the selection `proj_object_here` (`0x8007F9E8`) takes (Rayden's slot `0x43` → `0x800B9B04`);
  - **values from the parent**: the parent writes the child process's `+0x440` after `proj_process` (Rayden: his argument, 0 for D,F; Reptile: the forceball speed). The decompiler now takes known process fields (`decompile(..., fields)`), and folds a branch with a known condition to that path's values; an unconditional jump to the end of a branch arm (IDO's ternary) is no longer unstructured;
  - also: a `begin_special` that names its action keeps it when MKT changes the action later (Acid Spit's `0x604`: noted), and `stamp_tick` becomes `stamp` (its key the stamped word).

MKT `0x8002A750(amplitude, count)` starts a process that every 3 ticks moves the vertical camera offset by the amplitude and flips its sign, `count` times. The host keeps camera shake offsets at `0x8009A928` (vertical) and `0x8009A92C` (horizontal); its camera update adds them, and its own shake (process `0x15` at `0x80037CA0` → `0x80037A24`, called across the stages) plays a 16-step table from them and zeroes them. Its shortest run is 16 steps against MKT's 6, so the new `shake_screen` step runs MKT's algorithm on `0x8009A928` in a payload process (id `0x15`) and zeroes it at the end. 6 MKT px = 12 world units.

- **Colours** (Static-confirmed cause). Median cut merged across hues: black with the heavily used darkest green (the black undersuit turned green), and two greys with skin browns. MKT palettes are laid out as ramps (Reptile: 11 greys down to black, 7 greens, 13 browns). The `auto` method now keeps each ramp's colours apart: contiguous segments per ramp, 15 in all, with the least pixel-weighted error (exact arithmetic). A palette that is not laid out as ramps (3 of the 26 MKT fighters' palettes) falls back to median cut. The brown belt, flap and shin wraps are in the donor art.
- **Dead pose** (Static-confirmed cause). Host routes show only the first frame of the knockdown's second phase (`0x8005AC00`: `select_primary_phase2(0x1E)` and one `animation_advance`), and secondary 9 (lying) points at that phase. Stock Sub-Zero's phase is the single lying pose. Reptile's MKT landing is a bounce frame (`0x27C8`, legs up) and then lying (`0x27DC`). - **HP↔LP switch** (Static-confirmed cause). MKT scripts end at the loop, so the computed layout left those phases empty. When the imported script has the stock shape up to the loop, it now keeps the stock tail (tokens, operands, jumps) and translates each stock frame to the imported frame in the same place. This gives the same roles as Sektor's hand layout.
- **Pit fall** (unchanged): the held pose is the knockdown's last fall frame (`0x27B4`), as for Sektor.
- **Palette, v03** (Static-confirmed cause). v01 and v02 read Reptile's palette from `0x800A1738[19]`. **Composition v02 hang (static diagnosis of the owner's save state, 2026-11-13).**

- **Where:** the game thread (libultra thread 2) is *stopped by a CPU exception*: a TLB store miss (cause `0x0C`, bad address `0x133216F8`) at stock `0x8001BF04`, in the frame reader `0x8001BDA0` that the script interpreter calls at `0x80030E3C`. It runs on the hit enemy's process stack. The other threads only wait, and the CPU idles, so the screen freezes.
- **Why:** the enemy is a Temple MONK3 (actor type `0x78 = 2`). Its own fighter file has only six primary roots filled (`0`, `3`, `0x0E`, `0x1C`, `0x1D`, `0x2B`); roots up to `0x28` are otherwise `0xFFFFFFFF`, and the rest are 0. The forceballs' knockback reaction is a copy of host reaction `0x25` (`0x80057C14`). It plays the shared root `0x1E` through `0x800321D0` (sixth argument) with no morph first. So the script cursor became file base − 1, and a pixel word was read as a texture-slot number.
- **What stock does:** the stock launch reaction `0x0C` (`0x80052898`) first calls `0x800572C4` and `0x80057478` on the victim. For type 2, `0x800572C4` rebinds the actor to MONK2's file (`0x801AE46C`, file `0x89`, where root `0x1E` is `+0x518`) and makes it type 1. Host `0x25` has no morph, so in stock it is never used on such enemies.
- **Static checks on the state:** Reptile's relocated blob in RAM equals the build relocated to its load address, except one runtime data word. All 17 refreshed pointers hold the expected values. The relocation is not the cause.
- **Other reactions:** the Reverse Elbow hold selects no animation, the acid stagger (a copy of the stock Fire trap stumble) already calls `0x800572C4`, and the roundhouse uses stock `0x0C`. Only the forceballs' knockback arc lacked the morph. Strong inference: the earlier proofs' forceball tests only hit enemies that need no morph.
- **Slide inputs (Pending):** in the save state, the native special lock `0x800BF308` is 1 while Reptile runs (action `0x30E`). The stock special recognizer `0x8003C9B4` skips every special input, Slide included, while the lock is set. The XP gate is not the cause: XP is 20000, and Slide's tier check evaluates current XP. The forceball still worked because it is a command-table move. The lock was set when the forceball began, so this post-crash state cannot show what set it before. A save state taken while slides fail (before any special) is needed.
